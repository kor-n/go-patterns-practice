# Практика реализации популярных паттернов в Go

| Пакет | Задача |
|---|---|
| `01-urlcheck` | Проверка доступности списка URL: последовательно и параллельно |
| `02-fanin` | Слить N каналов в один, с отменой через контекст |
| `03-debug` | Найти и починить ошибки в конкурентном коде |
| `04-cache` | Потокобезопасный кэш с TTL |
| `05-workerpool` | Пул из N воркеров: паника в воркере, отмена, остановка по первой ошибке |
| `06-firstok` | Первый успешный ответ из N реплик |
| `07-shutdown` | Остановка HTTP-сервера: in-flight запросы, дедлайн, фоновый воркер, порядок закрытия |
| `sidequest-syncpool` | Переиспользование буферов через sync.Pool |

Задачи идут по нарастанию сложности, решать следует по порядку. `sidequest-syncpool` необязательный, его можно делать в любой момент для ознакомления и понимания как и для чего использовать `sync.Pool`.

## Что делать

Условие каждой задачи лежит в комментарии к пакету, в начале файла с реализацией. Всё, что нужно для решения, написано там.

Править нужно только файлы с реализацией, тесты изменять не нужно.

```bash
go test ./... -race          # всё
go test ./01-urlcheck -race  # одну задачу
```

## Когда задача считается выполненной

1. Тесты зелёные с флагом `-race`.
2. `goleak` не ругается.

`goleak` проверяет, что после теста не осталось живых горутин. Если он красный, значит где-то горутина не может завершиться.

## Линтер

Конфиг в репозитории под golangci-lint **v2**, можно запускать для проверки чистоты кода или прочих недостатков / багов:

```bash
golangci-lint run
```
